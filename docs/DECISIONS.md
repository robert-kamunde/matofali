# Decisions

Each entry records a choice made during development, why, and whether Robert needs to confirm it. Where the design guide, the browser prototype and the implementation disagreed, the conflict is listed here rather than silently resolved.

| ID | Decision | Why | Needs Robert? |
| --- | --- | --- | --- |
| D-01 | Package the web game with **Capacitor 8** (8.5.3). | The audit found a working HTML5 canvas prototype; Capacitor reuses it and produces the Play Store `.aab`. Capacitor 8 defaults to minSdk 24 (Android 7.0) and targetSdk 36, which matches Google Play's requirement for new apps from 31 August 2026. | No |
| D-02 | Rewrite the prototype's single file into modules (engine, rules, levels, renderer, UI, i18n, audio, storage, platform) rather than wrap it as-is. | The prompt requires separated, data-driven, testable code. The prototype mixed all concerns in one closure and could not be unit tested. Its rules and art were kept. | No |
| D-03 | Speed formula `5 + 0.35 × (level − 1) + 0.8 × (round − 1)` with `level` counting up forever (5, 6, 7 …). | Matches the guide's examples exactly: level 1 = 5, level 4 = 6.05 ("about 6"), level 5 = 7.2. Verified by unit test. No discrepancy. | No |
| D-04 | **Cap ball speed at 14 units per step.** | The guide sets no ceiling. Without one, speed reaches ~21 by level 30 and the game becomes unplayable, which conflicts with "progresses indefinitely". 14 is reached around level 17 (round 5). The value lives in `src/config/rules.js` (`ball.maxSpeed`). | **Yes, confirm or pick another cap** |
| D-05 | Use at least 3 collision substeps, adding more at high speed so the ball never moves more than 3.5 units per substep. | The guide specifies 3 substeps "as the initial specification". At the capped speed 3 substeps move 4.7 units each, close to tunnelling risk on 16-unit bricks. Adaptive substeps keep collisions exact; a unit test fires the ball at max speed from 40 positions. | No |
| D-06 | No ball path may be flatter than 65° from vertical; multi-ball splits and brick bounces are limited to this. | Prevents near-horizontal endless bouncing (an edge case the prompt names). Paddle hits stay within the documented 60°. Multi-ball splitting ±30° from a ball already at 60° would otherwise produce a 90° (horizontal) ball. | No |
| D-07 | Round 2 and later add **one** extra hit (not one per round). Door wood stays at 3. | The guide's table lists only "hits from round 2"; the prototype does the same. Cumulative toughening was not specified. | Optional |
| D-08 | Launch angle is random within ±17° of vertical. | Prototype used ±0.3 rad (≈17°); the guide says "slight random angle". | No |
| D-09 | Keep the `INTERNET` permission in the Android manifest. | Android's WebView needs it to load the game from Capacitor's local `https://localhost` origin; without it pages fail to load. The game makes no network requests (verified by a browser test that records every request). Google Play does not list INTERNET as a dangerous permission. **Unverified on device.** | No |
| D-10 | Vibration uses `@capacitor/haptics`, which adds the normal-level `VIBRATE` permission. | Vibration is a required setting. No other permissions are requested. | No |
| D-11 | Removed the Google Services Gradle plugin from the Capacitor template. | Version 1 must not use Firebase or Google services. | No |
| D-12 | Default language mode is **bilingual** (Swahili first, English smaller beneath). Settings offer Swahili only and English only. | The guide says "Swahili is the main language and English sits beside it"; the prompt says Swahili is the default and the bilingual presentation is documented. Language names in the picker are shown in their own language so anyone can find theirs. | Optional |
| D-13 | The Android Back button: Play → Pause; Pause → Resume; level card or game over → Home; Settings / How to play → Home; Privacy → Settings; Home → exit app. | The guide only says Back pauses. This mapping never loses progress by accident. | Optional |
| D-14 | Returning from the background leaves the game paused; the player taps Endelea to resume. | Auto-resume would drop the ball on someone who is not looking. | No |
| D-15 | The wide paddle is kept when moving to the next level (until it expires or a life is lost). | Matches the prototype. The guide is silent. | No |
| D-16 | The level 1 flag was redrawn as a full diagonal (the prototype had empty corner cells), and the Zanzibar door was made symmetric with a centre seam. | Closer to the guide's description; both still use the documented multi-hit bricks. | No |
| D-17 | Privacy policy is shown inside the app (works offline) and also provided as `docs/privacy-policy.html` for hosting. | Google Play needs a public URL. No URL was invented. | **Yes, host it and give the URL** |
| D-18 | Application ID `com.matofali.game`. | Must be unique on Google Play and **can never change after the first upload**. | **Yes, confirm before first upload** |
| D-19 | Fonts Bungee and Outfit are bundled from the `@fontsource` npm packages (SIL Open Font License 1.1), Latin subset only. | Offline, licence verified, about 60 KB. | No |
| D-20 | Sound effects are synthesised in code with Web Audio. No audio files. | No licensing risk, nothing to download. | No |
| D-21 | Dev tools pinned: Vite 8.3.4, Vitest 4.1.12, ESLint 9.39.0, Playwright 1.63.0. | Earlier Vite/Vitest versions had published security advisories. Remaining `npm audit` warnings are in build-only tools (`@capacitor/cli`'s `tar`, `@capacitor/assets`'s `sharp`), not in the shipped app. | No |
| D-22 | Android builds run on **GitHub Actions** (`.github/workflows/android.yml`). | The cloud machine used for development cannot reach Google's Android download server (`dl.google.com` returns 403), so Gradle cannot fetch the Android Gradle Plugin there. GitHub's runners include the Android SDK. | **Yes, create a GitHub repo** |
